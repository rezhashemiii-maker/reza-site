# سایت شخصی رضا هاشمی

سایت استاتیک، فارسی و راست‌به‌چپ — بدون فریم‌ورک و بدون وابستگی npm در ساخت یا اجرای سایت.

## صفحه‌ها

سایت ۸۴ صفحهٔ عمومی دارد: ۲۲ صفحهٔ اصلی، ۶۰ صفحهٔ پروژه در مسیر مهندس هوش مصنوعی و دو صفحهٔ مستقل. صفحهٔ ۴۰۴ جدا از این تعداد است. فهرست قابل انتشار در `tools/pages.mjs` تعریف می‌شود؛ ساخت، sitemap و لینک‌های صفحهٔ ۴۰۴ از همین فهرست استفاده می‌کنند.

صفحهٔ خانه در `index.html` است. واژه‌نامهٔ ۲۸۵ اصطلاحی در `glossary.html`، مسیر هشت‌ایستگاهی در `learn.html`، شصت صفحهٔ پروژه در `ai-engineer.html` و صد ایده در `ideas.html` قرار دارند. مطالعهٔ موردی دُرّین و دموی پایش سالن در `dorrin.html` و `demo.html` هستند. `agri-invest.html` و `iraq.html` دو صفحهٔ مستقل‌اند.

«صفحهٔ پروژه» لزوماً راهنمای کامل آموزشی نیست؛ بعضی صفحات هنوز بخش «به‌زودی» دارند. این تفکیک در برنامه‌ریزی محتوا مهم است.

## ساختار و منبع حقیقت

```text
src/*.dc.html          منبع صفحات قالبی؛ محتوا را این‌جا ویرایش کنید
src/partials/          هدر و فوتر مشترک هشت صفحهٔ اصلی
public/pages/          منبع HTML صفحات مستقل کشاورزی و عراق
public/assets/         فایل‌های ثابت دست‌نویس، از جمله تصویر پیش‌نمایش لینک
tools/                ابزارهای بدون وابستگی ساخت، پیش‌رندر و کنترل کیفیت
tests/                تست‌های واحد، یکپارچه و تست محدود مرورگر
docs/                 متن‌های مرجع و گزارش وضعیت بهبودها
dist/                 خروجی مستقل CI و انتشار؛ داخل Git ذخیره نمی‌شود
*.html و assets/       خروجی سازگار با انتشار قدیمی از ریشه؛ دست‌نویس نیستند
```

فایل‌های HTML ریشه و پوشهٔ `assets` خروجی ساخت هستند. برای صفحه‌های مستقل هم اکنون `public/pages` منبع حقیقت است؛ فایل ریشه را مستقیم ویرایش نکنید. فایل تصویر یا فونت جدید را در `public/assets` بگذارید، نه در `assets`، چون assets تولیدشده در هر ساخت بازسازی می‌شود.

جزء مشترک با `<dc-include name="header"></dc-include>` یا `<dc-include name="footer"></dc-include>` در قالب وارد می‌شود. سازنده آن را پیش از پارس گسترش می‌دهد و لینک صفحهٔ جاری را با `aria-current="page"` مشخص می‌کند. تمام خروجی نهایی HTML معمولی است و برای نمایش به این تگ سفارشی وابسته نیست.

## ساخت و پیش‌نمایش

Node ۲۲ در CI استفاده می‌شود. نیازی به `npm install` نیست.

```bash
SITE_URL=https://rezhashemiii-maker.github.io/reza-site OUTPUT_DIR=dist node tools/build.mjs
python3 -m http.server 8000 --directory dist
```

برای مشاهدهٔ محلی `http://localhost:8000/` را باز کنید. `SITE_URL` باید نشانی عمومی واقعی و بدون query یا fragment باشد؛ روی Pages پروژه‌ای، مسیر `/reza-site` بخشی از همین نشانی است. برای پیش‌نمایش بدون دامنه، متغیر را ندهید:

```bash
OUTPUT_DIR=dist node tools/build.mjs
```

در این حالت canonical، `og:url`، نشانی مطلق تصویر اشتراک‌گذاری و sitemap/robots تولید نمی‌شوند؛ URL ساختگی وارد خروجی نمی‌شود. ساخت مجدد بدون `SITE_URL` فایل sitemap/robots قبلی را از همان خروجی حذف می‌کند.

برای حفظ سازگاری با ساخت قدیمی، نبود `OUTPUT_DIR` یعنی خروجی در ریشهٔ مخزن. تا زمان تکمیل انتقال تنظیمات Pages، خروجی ریشه باید با منبع هماهنگ بماند:

```bash
SITE_URL=https://rezhashemiii-maker.github.io/reza-site node tools/build.mjs
```

## تست‌ها

```bash
node --test tests/*.test.mjs
SITE_URL=https://rezhashemiii-maker.github.io/reza-site OUTPUT_DIR=dist node tools/build.mjs
node tools/check-site.mjs dist
```

CI روی Pull Request و Push به `main` تست‌ها را اجرا می‌کند. کنترل کیفیت خروجی، متادیتا، sitemap، منابع محلی و لینک‌های داخلی را می‌سنجد. اگر `SITE_URL` به بررسی‌کننده داده نشود، نشانی را از canonical صفحهٔ خانه می‌خواند.

تست محدود مرورگر، جست‌وجو و فیلتر واژه‌نامه و ایده‌ها، روز بعد و بازنشانی دمو، و نمایش خانه و تماس در عرض ۳۷۵ پیکسل را کنترل می‌کند. این تست به سایت زنده وصل نمی‌شود و فرم یا پیامی ارسال نمی‌کند. وابستگی آن جدا از ساخت سایت است:

```bash
python3 -m pip install -r tests/requirements-browser.txt
python3 -m playwright install chromium
python3 tests/browser_smoke.py dist
```

این تست نیز در job مستقل CI اجرا می‌شود. تست خودکار لینک‌های خارجی، همهٔ تعاملات صفحات و بررسی جامع دسترس‌پذیری در این مرحله وجود ندارد.

## متادیتا و فایل‌های عمومی

صفحات اصلی در `tools/pages.mjs` توضیح اختصاصی دارند. توضیح صفحات پروژه از عنوان و نخستین پاراگراف همان منبع ساخته می‌شود. توضیح صفحات مستقل از head منبع آن‌ها خوانده می‌شود؛ هنگام ساخت، فقط متادیتای اشتراک‌گذاری و canonical استاندارد می‌شود و بدنه و اسکریپت صفحه حفظ می‌شود.

تمام صفحات عمومی دارای عنوان، توضیح، Open Graph و Twitter Card هستند. با `SITE_URL`، نشانی canonical و تصویر `assets/social-preview.png` نیز تولید می‌شود. تصویر با هویت بصری فعلی سایت ساخته شده است.

sitemap تمام ۸۴ صفحهٔ عمومی را شامل می‌شود و ۴۰۴ را حذف می‌کند. `lastmod` از تاریخ ثبت‌شدهٔ تغییر منبع در Git می‌آید، نه تاریخ هر Build؛ اگر تاریخ قابل اتکا در دسترس نباشد، این فیلد حذف می‌شود. در CI برای تاریخ کامل، checkout باید تاریخچهٔ Git را دریافت کند.

## انتشار روی GitHub Pages

ورک‌فلوی `.github/workflows/pages.yml` پس از تست، خروجی `dist` را منتشر می‌کند. هیچ سورس، تست یا فایل داخلی پروژه در artifact انتشار قرار نمی‌گیرد. ورک‌فلوی CI مربوط به Pull Request فقط مجوز خواندن دارد و انتشار نمی‌کند.

**تنظیم ضروری پس از پذیرش تغییرات:** در **Settings → Pages → Source** گزینهٔ **GitHub Actions** را انتخاب کنید. انتشار مبتنی بر شاخه و این ورک‌فلو نباید هم‌زمان فعال بمانند؛ در تاریخچهٔ فعلی خطای تداخل انتشار ثبت شده است. تغییر این تنظیم و تعیین دامنهٔ سفارشی در این Pull Request انجام نشده است.

نشانی فعلی سایت: <https://rezhashemiii-maker.github.io/reza-site/>. اگر دامنه تغییر کرد، آن را در تنظیمات Pages تعیین کنید تا `steps.pages.outputs.base_url` مبنای ساخت انتشار باشد. نشانی ثابت داخل CI صرفاً برای کنترل ساخت است و دامنهٔ تولید را تنظیم نمی‌کند.

## مشارکت و حقوق استفاده

[راهنمای مشارکت](CONTRIBUTING.md) مراحل ویرایش و ارسال تغییر را توضیح می‌دهد. برای گزارش مشکل، قالب Issue و برای ارسال اصلاح، قالب Pull Request موجود است.

مجوز استفاده از کد و محتوا هنوز توسط صاحب اثر انتخاب نشده؛ عمومی‌بودن مخزن جایگزین اعلام مجوز نیست. این تغییرات به‌طور خودکار مجوزی به اثر اضافه نمی‌کنند.

## فونت و حریم خصوصی

متن با Vazirmatn از Google Fonts بار می‌شود و در صورت در دسترس نبودن، فونت سیستمی جایگزین می‌شود. این بهبودها ابزار ردیابی، تبلیغات، ثبت‌نام یا سرویس جمع‌آوری ایمیل اضافه نمی‌کنند.
