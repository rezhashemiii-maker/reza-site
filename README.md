| کتاب‌های امنیت | `security.html` | نقشهٔ ۶۱ اثر بنیادین امنیت و ۱۹ حملهٔ تاریخی روی یک خط زمان، با تحلیل اثرگذاری |
| آزمون سواد | `literacy.html` | سنجش تعاملی سواد هوش مصنوعی: ۳۰ سؤال، نیمرخ شش‌بعدی و تحلیل کامل |

| کتابخانه | `library.html` | کتابخانهٔ یکپارچهٔ ۱۶۸ منبعِ ارجاع‌شده در کل سایت — جست‌وجو و فیلتر زنده |

## ساختار

```
src/          آرتبوردهای اصلی (.dc.html) — منبع حقیقت محتوا
  standalone/   صفحه‌های HTML خودبسنده که همان‌طور که هستند کپی می‌شوند
tools/        اسکریپت ساخت + رانتایم مرورگر
  parse.mjs     پارسر کوچک HTML
  compile.mjs   قالب → AST فشرده + استخراج کلاس‌های CSS
  render.mjs    AST → HTML (پیش‌رندر در زمان ساخت)
  dc.js         رانتایم ~۴.۷ کیلوبایتی مرورگر برای صفحه‌های تعاملی
  build.mjs     خط لولهٔ ساخت
assets/       خروجی: CSS و JS تولیدشده  ← دست‌نویس نیست
*.html        خروجی: صفحه‌های سایت      ← دست‌نویس نیست
```

محتوا را در `src/*.dc.html` ویرایش کنید، نه در فایل‌های ساخته‌شده.

## ساخت

```bash
node tools/build.mjs
```

بدون نصب چیزی، فقط Node ۱۸ به بالا. برای تولید `sitemap.xml` و `robots.txt` و
تگ `canonical`، نشانی سایت را بدهید:

```bash
SITE_URL=https://example.com node tools/build.mjs
```

## چطور بهینه شده

- **پیش‌رندر در زمان ساخت.** قالب‌های پویا (`{{…}}`، `<sc-for>`، `<sc-if>`) در
  زمان ساخت با حالت اولیه رندر می‌شوند، پس محتوای هر صفحه بدون جاوااسکریپت هم
  کامل خوانده می‌شود و موتور جست‌وجو آن را می‌بیند.
- **استخراج استایل‌های تکراری.** ۴۰۹ مقدار `style` تکرارشونده به کلاس‌های CSS
  کوتاه تبدیل شده‌اند؛ آن‌هایی که بیش از یک صفحه استفاده می‌شوند در
  `assets/site.css` مشترک‌اند و بقیه در CSS همان صفحه. برای حفظ دقیقِ ترتیب
  آبشار، قاعده‌ها به شکل `.x.x{…}` نوشته می‌شوند تا ویژگی‌شان از قبل کم‌تر نشود.
- **جاوااسکریپت فقط جایی که لازم است.** پنج صفحهٔ ایستا (`index`، `pattern`،
  `learn`، `game-theory`، `patents`) هیچ اسکریپتی بار نمی‌کنند. چهار صفحهٔ تعاملی
  رانتایم مشترک ۴.۷ کیلوبایتی را می‌گیرند که بین صفحه‌ها کش می‌شود.
- **فایل‌های جدا و کش‌پذیر.** داده و منطق هر صفحهٔ تعاملی در فایل `assets/*.js`
  خودش است و با `defer` بار می‌شود؛ رندر اول به آن وابسته نیست.

اندازهٔ هر صفحه پس از فشرده‌سازی gzip (چیزی که کاربر واقعاً می‌گیرد):

| صفحه | HTML | JS | جمع با CSS مشترک |
| --- | --- | --- | --- |
| خانه | ۹ کیلوبایت | — | ~۱۲ کیلوبایت |
| واژه‌نامه | ۲۶ کیلوبایت | ۳۱ کیلوبایت | ~۶۱ کیلوبایت |
| ایده‌ها | ۲۰ کیلوبایت | ۲۲ کیلوبایت | ~۴۶ کیلوبایت |
| دموی زنده | ۱۰ کیلوبایت | ۱۷ کیلوبایت | ~۳۱ کیلوبایت |

## انتشار

با هر پوش روی شاخهٔ `main`، ورک‌فلوی `.github/workflows/pages.yml` سایت را
می‌سازد و روی GitHub Pages منتشر می‌کند. برای فعال‌کردن، در تنظیمات مخزن
**Settings → Pages → Source** را روی **GitHub Actions** بگذارید.

## همگام‌سازی با آرتیفکت

این مخزن و آرتیفکت طراحی روی claude.ai یک محتوا را نگه می‌دارند، با **یک استثنای عمدی**:

- `Campaign.dc.html` (کمپین قارچ رنگی) فقط روی آرتیفکت است و **نباید** به این مخزن اضافه شود.
- به همین دلیل `Main.dc.html` روی آرتیفکت یک بخش «کمپین‌ها» بیشتر دارد.
- بقیهٔ آرتبوردها باید روی هر دو و یکسان باشند.

پس هنگام انتشار `Main.dc.html` روی آرتیفکت، نسخهٔ آرتیفکت را بخوانید و تغییرات را
روی همان اعمال کنید؛ نسخهٔ مخزن را جایگزین نکنید، وگرنه بخش کمپین‌ها پاک می‌شود.
