## ساختار

```
src/          آرتبوردهای اصلی (.dc.html) — منبع حقیقت محتوا
  standalone/   صفحه‌های HTML خودبسنده که همان‌طور که هستند کپی می‌شوند
tools/        اسکریپت ساخت + رانتایم مرورگر
  parse.mjs     پارسر کوچک HTML
  compile.mjs   قالب → AST فشرده + استخراج کلاس‌های CSS
  render.mjs    AST → HTML (پیش‌رندر در زمان ساخت)
  dc.js         رانتایم ~۴.۷ کیلوبایتی مرورگر برای صفحه‌های تعاملی
  build.mjs     خط لولهٔ ساخت
  check-links.py  بررسی همهٔ پیوندهای داخلی و لنگرها
  gen/          ژنراتورهای صفحه‌های تولیدی ← منبعِ src/
    run.py        همه را به ترتیب درست اجرا می‌کند
    paths.py      ریشهٔ مخزن، نسبت به خود فایل
    a16/ chess/ sec/ serv/ lib/ books/   داده + صفحه‌ساز هر پروژه
    port.py       انتقال آرتبوردهای آرتیفکت به src/
    lessons.py    پرکردن راهنمای ۶۰ صفحهٔ پروژه
    artifact/     صادرات خام آرتبوردها ← ورودی port.py، دستی ویرایش نشود
assets/       خروجی: CSS و JS تولیدشده  ← دست‌نویس نیست
*.html        خروجی: صفحه‌های سایت      ← دست‌نویس نیست
```

## چه چیزی را کجا ویرایش کنیم

سه لایه داریم و ویرایش باید همیشه در بالاترین لایه انجام شود:

| اگر می‌خواهید… | فایل را این‌جا عوض کنید | بعد اجرا کنید |
| --- | --- | --- |
| محتوای یک صفحهٔ تولیدی (کتابخانه، شطرنج، امنیت، سرویس‌ها، سواد، کتاب‌ها) | `tools/gen/<نام>/data.py` | `python3 tools/gen/run.py <نام>` سپس `node tools/build.mjs` |
| محتوای یک صفحهٔ دست‌نویس | `src/*.dc.html` | `node tools/build.mjs` |
| صفحه‌ای که از آرتیفکت می‌آید | روی خودِ آرتیفکت، بعد صادرات تازه در `tools/gen/artifact/` | `python3 tools/gen/run.py port` |
| پاک‌سازی‌هایی که موقع انتقال انجام می‌شود | `tools/gen/port.py` | `python3 tools/gen/run.py port` |

`assets/` و `*.html` خروجی‌اند و هیچ‌وقت نباید دستی عوض شوند.

ساخت کامل و بررسی:

```
python3 tools/gen/run.py     # src/ را از tools/gen/ می‌سازد
node tools/build.mjs         # src/ را به *.html و assets/ می‌سازد
python3 tools/check-links.py # هیچ پیوند یا لنگر شکسته‌ای نباشد
python3 tools/audit.py       # تیتر، شناسهٔ تکراری، alt، rel و طول متا
```

ورک‌فلوی انتشار هر چهار را اجرا می‌کند و اگر `src/` با `tools/gen/` نخواند،
انتشار را متوقف می‌کند.

## ساخت

```bash
node tools/build.mjs
```

بدون نصب چیزی، فقط Node ۱۸ به بالا. برای تولید `sitemap.xml` و `robots.txt` و
تگ `canonical`، نشانی سایت را بدهید:

```bash
SITE_URL=https://example.com node tools/build.mjs
```

## چطور بهینه شده

- **پیش‌رندر در زمان ساخت.** قالب‌های پویا (`{{…}}`، `<sc-for>`، `<sc-if>`) در
  زمان ساخت با حالت اولیه رندر می‌شوند، پس محتوای هر صفحه بدون جاوااسکریپت هم
  کامل خوانده می‌شود و موتور جست‌وجو آن را می‌بیند.
- **استخراج استایل‌های تکراری.** ۴۰۹ مقدار `style` تکرارشونده به کلاس‌های CSS
  کوتاه تبدیل شده‌اند؛ آن‌هایی که بیش از یک صفحه استفاده می‌شوند در
  `assets/site.css` مشترک‌اند و بقیه در CSS همان صفحه. برای حفظ دقیقِ ترتیب
  آبشار، قاعده‌ها به شکل `.x.x{…}` نوشته می‌شوند تا ویژگی‌شان از قبل کم‌تر نشود.
- **جاوااسکریپت فقط جایی که لازم است.** پنج صفحهٔ ایستا (`index`، `pattern`،
  `learn`، `game-theory`، `patents`) هیچ اسکریپتی بار نمی‌کنند. چهار صفحهٔ تعاملی
  رانتایم مشترک ۴.۷ کیلوبایتی را می‌گیرند که بین صفحه‌ها کش می‌شود.
- **فایل‌های جدا و کش‌پذیر.** داده و منطق هر صفحهٔ تعاملی در فایل `assets/*.js`
  خودش است و با `defer` بار می‌شود؛ رندر اول به آن وابسته نیست.

اندازهٔ هر صفحه پس از فشرده‌سازی gzip (چیزی که کاربر واقعاً می‌گیرد):

| صفحه | HTML | JS | جمع با CSS مشترک |
| --- | --- | --- | --- |
| خانه | ۹ کیلوبایت | — | ~۱۲ کیلوبایت |
| واژه‌نامه | ۲۶ کیلوبایت | ۳۱ کیلوبایت | ~۶۱ کیلوبایت |
| ایده‌ها | ۲۰ کیلوبایت | ۲۲ کیلوبایت | ~۴۶ کیلوبایت |
| دموی زنده | ۱۰ کیلوبایت | ۱۷ کیلوبایت | ~۳۱ کیلوبایت |

## انتشار

با هر پوش روی شاخهٔ `main`، ورک‌فلوی `.github/workflows/pages.yml` سایت را
می‌سازد و روی GitHub Pages منتشر می‌کند. برای فعال‌کردن، در تنظیمات مخزن
**Settings → Pages → Source** را روی **GitHub Actions** بگذارید.

## همگام‌سازی با آرتیفکت

این مخزن و آرتیفکت طراحی روی claude.ai یک محتوا را نگه می‌دارند، با **یک استثنای عمدی**:

- `Campaign.dc.html` (کمپین قارچ رنگی) فقط روی آرتیفکت است و **نباید** به این مخزن اضافه شود.
- به همین دلیل `Main.dc.html` روی آرتیفکت یک بخش «کمپین‌ها» بیشتر دارد.
- بقیهٔ آرتبوردها باید روی هر دو و یکسان باشند.
- «پروندهٔ عراق» روی هر دو هست، ولی در دو قالب: در این مخزن یک صفحهٔ خودبسنده
  (`src/standalone/iraq.html` → `iraq.html`) و روی آرتیفکت یک آرتبورد
  (`Iraq.dc.html`). هر دو از همان یک فایل می‌آیند؛ نسخهٔ آرتبورد فقط استایل را
  به `<helmet>` و اسکریپت را به `componentDidMount` منتقل می‌کند. پس هر تغییری
  باید در `src/standalone/iraq.html` انجام شود و بعد به آرتبورد تبدیل شود.

- آرتبوردهای آرتیفکت در `tools/gen/artifact/` به‌صورت خام نگه داشته می‌شوند و
  `tools/gen/port.py` آن‌ها را به `src/` منتقل می‌کند. برای هر تغییر در این
  صفحه‌ها، اول روی آرتیفکت تغییر بدهید، بعد صادرات تازه را در همان پوشه
  بگذارید و `python3 tools/gen/run.py port` را اجرا کنید.
- ساختار ناوبری آرتیفکت با مخزن فرق دارد: آن‌جا «نوشته‌ها» آرتبورد جداگانه‌ای
  به نام `Writing.dc.html` است. پس در نسخهٔ آرتیفکتِ هر صفحه، پیوند بازگشت
  `Main.dc.html#writing` باید به `Writing.dc.html` تبدیل شود — همین و بس.

پس هنگام انتشار `Main.dc.html` روی آرتیفکت، نسخهٔ آرتیفکت را بخوانید و تغییرات را
روی همان اعمال کنید؛ نسخهٔ مخزن را جایگزین نکنید، وگرنه بخش کمپین‌ها پاک می‌شود.
کارت هر نوشتهٔ تازه باید هم در `src/Main.dc.html` مخزن و هم در `Writing.dc.html`
آرتیفکت اضافه شود، و نام آرتبورد تازه در `canvas.json` (هم `boards` و هم `order`).
